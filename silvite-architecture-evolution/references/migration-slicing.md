# Migration Slicing

## 切片准入

一个迁移切片必须产生单一用户或系统可观察结果，并能独立回滚。每片记录：

| 字段 | 内容 |
|---|---|
| ID / 目标 | 唯一标识和可观察结果 |
| 入口 | 当前入口与目标入口 |
| 不变量 | 行为、身份、数据、兼容和排除范围 |
| 影响面 | 文件、模块、平台、edition、仓库、外部系统 |
| 兼容 | 新旧共存、适配、协商和窗口 |
| 证据 | 先失败的目标测试、回归、构建、产物、实机/安装 |
| 回滚 | Commit、开关、产物、数据恢复和验证信号 |
| 启用 | 进入有限或默认路径的证据门槛 |
| 退役 | 所有消费者迁移、窗口结束、fallback 验证和删除条件 |
| 状态 | Planned / Implemented / Verified / Migrated / Retired |

没有明确退役条件的兼容层容易永久化；没有明确启用条件的新实现不得接管默认路径。

## 状态语义

- `Planned`：合同、范围、测试、回滚和依赖已定义，尚未写入。
- `Implemented`：源码存在，尚未取得全部切片证据。
- `Verified`：目标测试、相关回归和要求的环境证据已通过，但尚未成为目标路径。
- `Migrated`：目标消费者已切换，新路径在约定范围运行，fallback 仍保留。
- `Retired`：兼容窗口结束，全部消费者和回滚策略验证后旧实现已删除。

不得跳级，也不得用代码合并时间自动推进状态。

## 依赖顺序

默认串行顺序：契约/模型 → 纯逻辑 → 平台适配 → 状态机 → 调用方 → UI → 构建/打包 → 发布。

只有当两个切片不修改同一文件、不拥有同一状态、不改变同一协议/行为边界且能独立验证和回滚时，才允许并行写入。高耦合路径、共享生成器和版本身份始终指定一个写入者。

## 每片验证循环

1. 写出能捕获行为变化的目标测试并观察预期失败。
2. 实现最小目标路径，保留旧路径和明确选择机制。
3. 运行目标测试与相关全量回归。
4. 构建所有受影响平台和 edition。
5. 检查产物身份、内容、签名和文件名。
6. 根据风险执行真机、真实安装、升级、断连、恢复或 fallback 验证。
7. 用 Git diff 和仓库状态检查影响面与明确排除项。
8. 记录原始命令、退出码、时间、环境和产物哈希，再推进状态。

## 旧实现退役

同时满足以下条件才删除旧实现：所有已知调用方已迁移；兼容窗口结束；目标环境证据新鲜；监控能区分新旧失败；fallback 不依赖待删除代码，或新的回退路径已演练；Dead Code 搜索和公共接口检查完成；发布/回滚文档同步。

## 停工与恢复记录

每次可能中断前保存：

```text
时间与负责人：
当前阶段：
已完成切片及证据：
未完成切片及停止位置：
分支 / HEAD / 工作树 / 未跟踪文件：
最近测试命令与完整结果：
最后 Known-Good Commit / 产物：
当前启用路径与 fallback：
下一步唯一入口：
未验证风险与人工决策：
```

恢复时先核对记录与当前 Git/环境是否一致。任何漂移都成为新事实；不得用“主要完成”“差不多可用”推断状态。

# Cross-Platform and Editions

## 共享语义，不强求共享源码

跨平台、edition 和仓库先定义必须一致的行为与契约，再决定是否共享实现。平台生命周期、权限、打包、更新和外部 API 不同时，保持不同源码可以是正确边界。

目录、补丁或 Commit 相同不是验收标准。不同仓库经过语义移植后产生不同 Commit 是正常结果。

## 同步矩阵

迁移前为每个能力填写：

| 类别 | 仓库/平台 A | 仓库/平台 B | 同步目标 | 禁止带入 |
|---|---|---|---|---|
| 核心契约与行为 | 是否存在 | 是否存在 | 语义一致 | edition 特有分支 |
| 平台适配 | 实现与权限 | 实现与权限 | 相同上层契约 | 平台 API/包身份 |
| edition 能力 | 可用范围 | 可用范围 | 明确隔离或协商 | 授权、更新器、凭据 |
| UI 公共行为 | 页面/状态 | 页面/状态 | 用户结果一致 | 内部身份字段 |
| 发布逻辑 | 渠道/manifest | 渠道/manifest | 各自可验证 | 另一仓库发布配置 |
| 数据与内容 | 格式/来源 | 格式/来源 | 兼容格式 | 可执行代码或秘密 |

机械 cherry-pick 前先分类每个 diff hunk。属于一端专有、路径不同、发布不同或凭据边界的内容必须排除或语义重写。

## 平台能力边界

LAN、Wi-Fi Direct、Bluetooth、USB 或其他传输共享能力语义、状态事件和错误分类；不要强迫共享平台 API、权限请求或生命周期实现。

平台适配层负责：能力探测、权限、资源生命周期、系统事件到稳定领域事件的映射，以及平台特有错误。上层不得根据平台类型散布分支来修补错误抽象。

## Edition 隔离

- 核心不得反向依赖某个可选 edition。
- 官方/商业能力通过明确组合或能力注册进入，不渗入社区默认路径。
- 更新器、授权、发布渠道和凭据始终留在所属 edition/仓库。
- 缺少可选能力时核心提供明确降级和可观察状态。
- 同步测试分别在每个 edition 构建，不能用一个 edition 的通过外推另一个。

## 排除范围证明

对明确排除的平台或仓库：限制生成器输入与输出；执行前预览目标文件；执行后检查 Git status/diff；记录零修改证据。共享脚本能写到排除仓库不构成授权。

## 分仓验证

每个仓库独立验证契约、测试、构建、包身份、发布清单和回滚。最后用跨仓兼容实验验证行为，而不是比较 Commit 是否一致。

# Baseline and Invariants

## 冻结基线

跨模块写入前建立可读取、可恢复、带时间的基线：

| 类别 | 必须记录的证据 |
|---|---|
| 源码 | 仓库、分支、HEAD、远端、工作树、未跟踪文件、子模块或 worktree |
| 发布身份 | ProductVersion、Build、Commit、Channel、edition、平台 |
| 产物 | 当前正式包、文件名、哈希、签名身份、manifest/Tag/Asset 对应关系 |
| 行为 | 双端或多端 Known-Good 核心流程、错误与恢复行为 |
| 数据 | 用户数据、配置、凭据引用、缓存位置及兼容格式 |
| 升级 | 包 ID、UpgradeCode 或平台等价身份、最低支持版本、升级路径 |
| 质量 | 测试清单、最近一次完整结果、真机/真实安装证据、已知 Bug |
| 回滚 | 精确 Commit、正式产物、配置/数据恢复步骤、耗时与验证信号 |

先验证备份或产物可读取、旧版本仍可运行、回滚身份兼容以及恢复后的状态一致性。只有文件存在不等于可恢复。

脏工作树与迁移范围重叠时，使用隔离工作区或经验证的补丁/快照保护原改动。无法建立恢复点时停止写入。

## 定义不变量

把不变量写成可观察、可测试的约束，并标注责任层：

- 用户关键流程及其错误/取消/重试行为；
- 应用、包、升级、协议、设备和持久化身份；
- 用户数据目录、配置格式与迁移语义；
- 旧版本、旧协议和兼容窗口内消费者；
- 平台与 edition 能力隔离；
- 可选模块失败时核心仍可工作的降级行为；
- Discovery、Connecting、Authenticated、Ready 等状态的权限边界；
- 内容更新与可执行代码更新的信任边界；
- 普通 UI 不应获得或显示的内部信息；
- 明确排除的模块、平台、仓库和生成输出必须保持零修改。

对每条不变量记录验证方法、失败信号、当前证据和允许改变它的人工决策者。目标架构无法保持某条不变量时，先重新订立迁移合同，不得把变化隐藏为实现细节。

## 信息暴露矩阵

以下是默认上限；具体项目可进一步收紧，但不得放宽凭据规则：

| 信息 | 普通 UI | 开发者日志 | 崩溃报告 | 包属性 | 网络请求 | 更新器 | 发布清单 |
|---|---:|---:|---:|---:|---:|---:|---:|
| ProductVersion | 是 | 是 | 是 | 是 | 必要时 | 是 | 是 |
| Build | 否 | 是 | 是 | 是 | 必要时 | 是 | 是 |
| Commit | 否 | 是 | 必要时 | 可选 | 必要时 | 可选 | 是 |
| Channel | 必要时 | 是 | 是 | 可选 | 必要时 | 是 | 是 |
| Token/密钥 | 否 | 否 | 否 | 否 | 仅受保护协议所需 | 内部受控 | 否 |
| 错误码 | 必要时 | 是 | 是 | 否 | 协议所需 | 是 | 否 |
| 诊断详情 | 否 | 是 | 脱敏后 | 否 | 最小必要 | 必要时 | 否 |

不要把包含全部字段的共享身份对象直接交给 UI。按消费者建立最小视图或明确映射，在编译、序列化和日志边界验证未泄漏字段。

## 基线完成条件

只有同时满足以下条件才能标记基线已冻结：

1. 所有记录都有实际值或明确的 `Unknown` 及其影响；
2. 回滚点与产物可访问且恢复步骤经过验证或等价演练；
3. 工作树保护机制可恢复；
4. 不变量拥有观察信号和责任层；
5. 未知项不会让第一迁移切片产生不可逆风险。

# Hermetic Toolchains

## 目标

让构建、设备操作和发布实际使用预期的随包工具、版本、环境与缓存。工具“在机器上可运行”不能证明构建可复现。

## 执行门禁

对 ADB、Git、runtime、编译器、打包器和签名工具记录：

1. 解析后的绝对可执行路径；
2. `--version` 或等价版本输出；
3. PATH、HOME 类工具状态目录、SDK/运行时变量和配置来源；
4. 子进程继承或重写的环境；
5. 缓存、daemon、设备 server、临时目录与凭据存储位置；
6. 命令行、工作目录、退出码和关键输出；
7. 网络依赖、离线行为和锁定的依赖版本。

不要依赖命令名解析。使用显式路径或由受测启动器返回的确定路径，并在日志中记录最终解析结果。

## 隔离系统环境

- 构造最小环境，而不是继承整个交互式 shell。
- 为工具状态使用任务专用目录，不复用用户全局配置或缓存。
- 检查 wrapper、脚本和子进程是否重新搜索 PATH。
- 区分随包工具启动的 daemon 与系统已有 daemon；验证协议/版本兼容。
- 失败时不得静默回退到系统工具。需要 fallback 时把它建模为显式、可观察、经过验证的策略。

不要覆盖系统常用环境变量来实现隔离；使用任务专用变量和显式参数。

## 设备工具示例门禁

内置设备工具运行前后核对可执行路径、客户端/服务端版本、server 端口、设备列表来源和日志。若系统已有服务影响结果，停止并在隔离端口或清晰受控环境重试，不通过杀死未知系统进程掩盖冲突。

## 验证

在干净环境和受控污染环境各运行一次：向系统 PATH 放入不同版本，确认启动器仍选择随包工具，或明确失败而不回退。记录哈希可进一步证明执行的是目标二进制。

产物构建还必须锁定依赖、配置和生成输入；只固定主工具路径不足以称为 hermetic。

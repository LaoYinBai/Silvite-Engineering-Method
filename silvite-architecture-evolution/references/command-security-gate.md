# Command Security Gate

## 按行为链分类风险

“只读”“验证”“不执行下载结果”只描述局部意图。终端安全产品观察的是组合行为、数据流和信任边界。

执行命令前逐项回答：

| 问题 | 高风险信号 |
|---|---|
| 是否读取、解密、复原、导出或记录凭据？ | Token、Cookie、密钥、签名材料进入脚本或输出 |
| 是否反射加载程序集或调用非公开接口？ | 绕过受支持 API 和正常权限边界 |
| 是否下载或生成二进制？ | EXE、安装包、脚本、动态库或可执行内容 |
| 是否随后执行、加载、安装或签名？ | 下载到执行/持久化的连续链路 |
| 是否修改终端安全、白名单、隔离区或签名状态？ | 降低防护以使命令运行 |
| 组合行为是否类似凭据窃取、加载器或投递器？ | 单步看似合理但链路高度可疑 |
| 是否有不接触真实凭据的受支持替代？ | 正常客户端、测试凭据、签名 manifest、哈希/API |
| 是否需要用户对精确行为和环境明确授权？ | 管理员权限、真实资产或外部副作用 |

命中凭据复原、非公开接口与二进制下载的组合时停止该方案，即使它不写服务器、不执行文件或用户拥有管理员权限。

## 安全替代顺序

1. 使用正常产品客户端和公开接口观察结果。
2. 使用无生产权限、可撤销、范围受限的测试凭据。
3. 使用签名 manifest、发布元数据、哈希和包签名证明一致性。
4. 在不含真实秘密的隔离环境重放协议或下载流程。
5. 若仍需高风险链路，向用户展示精确命令、凭据流、二进制流、外部副作用、隔离和恢复计划，取得明确授权后再决定。

安全软件拦截是新的工程证据。不要建议关闭 Defender、禁用 EDR、恢复隔离文件或添加白名单来继续原行为链。先重新设计验证路径；若怀疑误报，走组织规定的样本审查和安全团队流程。

## 凭据处理

- 不从成品、内存、配置或私有函数复原生产凭据用于独立测试。
- 不把凭据写入命令行、日志、崩溃报告、剪贴板或评测材料。
- 最小化权限、作用域和有效期，使用后按授权流程撤销。
- 验证需要认证时优先让受支持客户端持有秘密，验证者只观察脱敏结果。

## 二进制与签名

下载验证优先读取元数据、长度、哈希、签名和 manifest，不需要执行即可证明的内容不要执行。必须运行时使用已授权沙箱、来源校验、网络限制、进程/文件审计和销毁流程；运行结果仍不能替代来源与签名验证。

## 报告状态

被安全门禁阻止时准确报告：原验证目标、被拒绝的行为链、已获得证据、安全替代、缺失证据和当前状态。不要把停止危险方案描述为发布验证失败，也不要把上传成功描述为远端已独立验证。

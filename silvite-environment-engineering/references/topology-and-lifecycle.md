# Topology and Lifecycle

## 建模目标

环境边界不是目录命名问题，而是所有权与生命周期问题。对每一层记录：

| 字段 | 问题 |
|---|---|
| 身份 | 当前命令实际上在哪一层执行？ |
| 所有权 | 谁拥有 HOME、PATH、配置、进程和状态文件？ |
| 启动 | 哪个上游层创建它？ |
| 消亡 | 哪个事件会终止或重建它？ |
| 映射 | 哪些目录、环境变量或 socket 跨层暴露？ |
| 能力 | 哪些命令只存在于特定层？ |

不要从提示符、用户名或 `/root` 推断宿主权限。容器、Proot、VM、WSL 与远程会话可能呈现类似路径，却具有不同的内核、权限和生命周期。

## Bootstrap Ownership

启动入口必须由目标环境启动前仍然存在的层拥有。检查链路：

```text
用户可到达的初始层
→ 启动入口
→ 隔离环境创建
→ 会话或服务创建
→ 目标能力 Ready
```

若入口只存在于目标环境内部，它最多证明 warm session 内可调用，不能证明 bootstrap。

## Warm、Fresh 与 Cold

- **Warm**：复用已有进程、socket、环境变量或已加载配置。
- **Fresh session**：创建同层新 Shell/进程，但上游服务可能仍在。
- **Cold**：按任务定义终止上游可变状态，再从用户唯一公开入口重建。

先写清 cold 的边界。关闭一个终端标签页不一定终止宿主应用；新建 Shell 也不一定重建桌面、容器或远程代理。

Cold 验收至少记录：前态清理证据、未执行的准备步骤、入口解析、完整启动链、Ready 探针、停止后的残留检查。无法观察 GUI 或设备行为时不得补写 PASS。

## 资产发现的边界

Inventory 先于替换，但 inventory 不等于复用：

1. 找到候选入口与配置。
2. 确认它们属于正确层和当前版本。
3. 检查实际调用关系，而非只看文件名。
4. 用目标生命周期验证候选路径。
5. 只有达到相应证据状态后才称为 proven path。

包内样例、历史快照或备份中的脚本不证明运行环境已经安装该脚本。
